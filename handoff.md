# Handoff — schools-map-mathex

## Цель проекта

Статический GitHub Pages-сайт с картой лучших школ и детских садов Москвы:

https://volgarevmaxim-bit.github.io/schools-map-mathex/

Репозиторий:

https://github.com/volgarevmaxim-bit/schools-map-mathex

## Ветки и публикация

- `main` — исходники;
- `gh-pages` — фактически опубликованный статический сайт;
- GitHub Pages должен использовать `gh-pages` / `/(root)`.

После изменений в `main` нужно отдельно обновить `gh-pages`, потому что push в `main` сам по себе не гарантирует обновление сайта.

Текущие изменения интерфейса в рабочем дереве ещё нужно закоммитить и опубликовать. Перед новой публикацией обязательно проверить `git status` и текущие commit IDs.

## Главные файлы

- `index.html` — заголовок, карта и единственный Markdown-контейнер после карты;
- `app.js` — Leaflet, фильтр, popup, обратные ссылки и встраивание адресов в Markdown;
- `places.json` — единственный актуальный источник объектов карты;
- `Лучшие школы Москвы.md` — редакционный исходный текст школ;
- `Лучшие детские сады Москвы.md` — редакционный исходный текст детских садов;
- `Schools_Session_Summary.md` — подробный журнал решений;
- `build_places.py` — проверка данных;
- старые `schools.geojson`, CSV, XLSX — исторические материалы, не источник текущего состава.

## Текущее UX-требование

Между картой и разделом **«Исходные описания из Markdown-файлов»** не должно быть отдельных карточек.

Внутри Markdown-раздела адрес и обратная ссылка должны находиться рядом с соответствующим описанием школы/сада. Нельзя выводить отдельные технические разделы:

- «Данные карты: адреса и переходы к точкам (школа)»;
- «Данные карты: адреса и переходы к точкам (детский сад)».

Ссылка `↗ Показать на карте` должна:

1. включить режим `all`;
2. перерисовать маркеры;
3. центрировать карту на объекте;
4. открыть popup объекта;
5. прокрутить страницу к карте.

## Слой данных

У каждого объекта должны быть:

- уникальный `id`;
- `name`;
- `entity`: `school` или `kindergarten`;
- `kind`: `green`, `blue`, `red`;
- `address`;
- `lat`, `lon`;
- `group` для связанных объектов;
- `associated_school` для детского сада;
- `source` для проверенного источника адреса, если есть;
- `notes` для оговорок.

Разные корпуса и разные здания школы/сада — разные объекты и разные координаты.

## Проверка перед commit

```bash
node --check app.js
python - <<'PY'
import json
p=json.load(open('places.json', encoding='utf-8'))
assert len(p) == 51
assert len({x['id'] for x in p}) == len(p)
assert all(x['address'] and x['lat'] and x['lon'] for x in p)
print('valid:', len(p))
PY
```

Проверить, что `index.html` не содержит старые контейнеры:

```bash
grep -E 'kind-cards|first-cards|other-cards' index.html
```

Команда должна вернуть пустой результат.

## Публикация

Сначала commit в `main`, затем скопировать в `gh-pages` минимум:

- `index.html`;
- `app.js`;
- `places.json`;
- оба Markdown-файла;
- `README.md`;
- `Schools_Session_Summary.md`;
- `.nojekyll`.

После push проверить именно опубликованную ветку:

```bash
curl -L https://raw.githubusercontent.com/volgarevmaxim-bit/schools-map-mathex/gh-pages/places.json
curl -L https://raw.githubusercontent.com/volgarevmaxim-bit/schools-map-mathex/gh-pages/app.js
```

Не считать push завершённым, пока live-файлы не содержат новую версию.

## Откат

Перед опасными изменениями создать commit. Откатить можно через:

```bash
git log --oneline --all
# затем git revert <commit>
```

Для GitHub Pages после отката `main` повторно обновить `gh-pages` и проверить live-файлы.

## Важные предупреждения

- Не использовать старый `schools.geojson` для восстановления текущего состава: он содержит старый список.
- Не объединять школу и детский сад только потому, что название организации одинаковое.
- Не угадывать адреса: сначала проверять официальный сайт/контакты.
- Не редактировать адреса в `index.html` или `app.js`; адреса живут в `places.json`.
- GitHub Pages CDN может временно отдавать старый файл; сравнивать с GitHub Raw и добавлять query-параметр cache bust при проверке.
- Текущий основной источник текста остаётся в двух Markdown-файлах; динамические адресные блоки строятся из `places.json`.

Подробные решения и история проекта находятся в `Schools_Session_Summary.md`.
