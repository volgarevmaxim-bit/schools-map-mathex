## Важное ограничение данных

Исходный GeoJSON содержит координаты и адреса, но не отдельные здания для всех организаций из Markdown. Поэтому карта показывает все здания, которые были в исходном GeoJSON; новые филиалы нужно добавлять отдельными Point-фичами с отдельными адресами и координатами. Это безопаснее, чем пытаться угадывать адреса.

## Архитектура обновлений

1. Редактировать `Лучшие школы Москвы.md` и/или `Лучшие детские сады Москвы.md`.
2. Для новой точки добавить объект в `schools.geojson` с координатами здания и описанием.
3. При необходимости обновить наборы `GREEN` и `BLUE` в `build_data.py`.
4. Запустить:

```bash
python build_data.py
```

5. Проверить сайт локально через HTTP-сервер, а не через `file://`:

```bash
python -m http.server 8000
```

6. Проверить четыре режима фильтра, popup-ссылки, прокрутку к карточке и отображение исходных Markdown.
7. Закоммитить изменения одним понятным коммитом.

## Как добавить школу или сад быстро

- **Только изменить текст:** править Markdown; карта не требует изменений, если точка уже существует.
- **Добавить здание:** добавить Point в `schools.geojson`; повторно запустить `python build_data.py`. Каждый корпус — отдельная точка, даже если название организации одинаковое.
- **Удалить здание:** удалить соответствующую Point-фичу из GeoJSON и пересобрать `app.js`.
- **Изменить категорию:** изменить название в `GREEN` или `BLUE` в `build_data.py`; зелёный имеет приоритет над синим.
- **Изменить координаты:** править только GeoJSON, затем пересобрать данные.

## Извлечённые уроки

- Основной источник геоданных должен быть отдельным от представления. HTML не должен содержать адреса вручную.
- Организация и здание — разные сущности: одна школа может иметь несколько Point-фич.
- Категории лучше хранить как правила/наборы в одном build-скрипте, а не размазывать по HTML.
- Для GitHub Pages нельзя использовать абсолютные пути к локальным файлам; все пути сделаны относительными.
- Маркеры сделаны через Leaflet и OpenStreetMap, поэтому сайт не требует API-ключа Яндекс.Карт.
- Markdown показывается на странице через `marked`; при изменении внешней зависимости следует зафиксировать её локально, если потребуется полностью автономный офлайн-сайт.
